# Broker Connectors Contributor Rules

This public workspace contains provider protocol adapters, provider-neutral read ports, and a separate provider-neutral execution software contract. Keep market reads, account reads, and execution authority separate. The library must not create a second OMS, account-state authority, quote store, persistence layer, or runtime scheduler.

## Safety Boundaries

- Tests use synthetic payloads and fake transport only. Never read local credentials, call OAuth, or contact a provider/account during development or validation.
- Production endpoints are fixed, HTTPS/WSS allowlisted values. Do not accept arbitrary production base URLs or enable redirects on credential-bearing requests.
- Credentials must be injected through an explicit provider boundary, redacted from `Debug`/errors/logs, and zeroized when owned by this crate.
- Market source/feed, provider timestamps, local receive time, generation, sequence, and encoding evidence remain explicit. Unknown entitlement stays unknown; no automatic IEX/indicative fallback is allowed. Received MessagePack application frames may travel only in the bounded ordered record lane; outbound authentication frames and credential material are never captured.
- Raw frame capture is limited to 1 MiB per frame, 16 MiB and 1,024 frame records process-wide. Each normalized event carries frame SHA-256, canonical generation, frame sequence, and 1-based ordinal/count. Unknown, malformed, provider-error, quote-coalesced, or otherwise incomplete input must fail closed and cannot be represented as a complete archive.
- `broker-ports::RawFrameSink` is an optional contract only until a reviewed sink is composed. A trusted sink owns one UUIDv4 per logical subscription, stable across reconnect generations and replaced after restart. Its pre-decode ACK binds capture ID/generation/sequence/frame SHA; its post-decode finalization ACK additionally binds the canonical bounded decode summary. ACK constructors only express the sink implementation's promise, not proof of `fsync`, source entitlement, Drive publication, or completeness. Sink queue/full, write/ambiguous failure, cancellation, or ACK mismatch poisons and terminates that generation; no decode, normalized event, or retry may pass the failed frame. Never store outbound authentication/token or potentially credential-echoing authentication diagnostics.
- Execution write transport and provider execution adapters remain absent. `broker-execution` defines only a typed software port; downstream callers cannot construct `Accepted`, and its non-default `offline-fake` feature accepts synthetic inputs and is not an actual broker. A Paper route is descriptive, not authority. Parsing or building an order is not a send capability.
- The read-only `alpaca-rest-read` consumer uses the scoped, pinned community SDK in `vendor/alpaca-rust`; Rust 1.99.0 is required for the workspace, while the shared workspace and `broker-execution` MSRV declarations remain 1.98.1. The wrapper requires explicit credentials, fixed HTTPS origin, redirects disabled, an 8 MiB response-body cap, and finite request/page/retry budgets. Its requested options feed and actual feed/entitlement evidence stay separate; historical option bars/trades and trusted watermarks are unsupported.
- The read-only `ibkr-read` crate depends on the pinned community SDK snapshot in `vendor/ibapi`, but exposes only an exact option-catalog query and provider catalog identity; keep the SDK client private and do not add account, market-data, history, or order methods to this wrapper. The adapter requires a complete OCC symbol, explicit non-`SMART` exchange/currency, a loopback address, per-phase connect/request/cancel/disconnect budgets in `(0, 60s]`, checked request/drain deadlines, bounded streamed rows, and native terminal confirmation. An aborted lookup poisons the session and drops the adapter's SDK owner because the SDK subscription's `Drop` only schedules cancellation and cannot confirm native END. Missing deliverable, exercise style, or settlement data must remain `Unknown`, so provider identity cannot qualify an option. It does not implement the generic `InstrumentCatalogPort`, whose current query omits required exact identity fields. Tests use only a synthetic loopback gateway; real TWS/Gateway, accounts, and orders remain `NOT RUN`. Remote gateway support requires separate trusted-network and permissions review.
- IBKR SDK diagnostics must never print raw request, handshake, decoded response, notice, or error payloads. Both the bidirectional `MessageRecorder` and inbound `RawFrameTap` stay disabled on production connections; `IBAPI_RECORDING_DIR` and `IBAPI_RAW_CAPTURE_DIR` do not enable persistence. Only tests may use explicit temporary-directory constructors with synthetic fixtures. Do not use real account traffic in tests or enable either capture for provider validation.
- New public types and critical invariants use English first, followed by Simplified Chinese.

The current item-scoped `dead_code` allowances in `broker-execution` preserve the Accepted state
and request-binding validator for a future reviewed in-crate provider adapter. The default build
contains no writer; the opt-in `offline-fake` feature is the only current constructor. Remove these
allowances once a reviewed adapter exercises the acceptance path without enabling the fake.

## Validation

Use the pinned toolchain and `CARGO_BUILD_JOBS=2`. Run the affected crate tests first, then workspace tests, formatting, Clippy with `-D warnings`, dependency/license checks, and secret scanning. Do not suppress numeric conversion or safety lints. The current item-scoped Clippy allowances are: `MarketNumber::to_f64` documents its intentionally lossy projection; the Alpaca request/control entrypoints, MessagePack preflight, and two session-state transitions keep their bounded state machine together; `receive_frame` keeps each protocol deadline explicit; the runner imports its parent's private session vocabulary; the fake socket implements the required async test trait without awaiting. Report native provider, OAuth, live-data, and Windows/macOS runtime checks as `NOT RUN` unless they were actually executed in an authorized environment.
